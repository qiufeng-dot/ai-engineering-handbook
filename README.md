# AI 工程学习手册

**从“模型答得不错”到“系统真的好用”：读懂原理、做出取舍、判断结果。**

这里整理了 AI 应用、Agent 设计、AI 辅助开发和软件测试四条学习路线。面向正在做 AI 产品、用 AI 写代码，或者想读懂相关论文的开发者与产品负责人。

每篇围绕一个具体问题展开：为什么原来的办法不够，新的机制怎样工作，证据支持什么，遇到哪些条件会失效。保留可以跟着算的小例子、原文出处和自测题。

## 四条学习路线

### 01 · AI 应用：先理解系统为什么会答错

大模型怎样工作 → 提示词与上下文 → 检索真实资料 → 工具调用与 Agent → 评测 → 用一个需求串起来。

[进入 AI 应用专题](docs/ai/README.md) · 包含 4 篇论文精读：长上下文、ReAct、模型评审与幻觉。

### 02 · Agent 设计：按瓶颈选择机制

ReAct → Plan-and-Solve → ReWOO → LLMCompiler → Self-Refine → Reflexion → LATS → Self-Discover → STORM。

[进入 Agent 专题](docs/agents/README.md) · 关注信息从哪里来、步骤怎样衔接、反馈是否可靠，以及多做一步要付出什么。

### 03 · AI 辅助开发：从一句需求到可用软件

最小开发知识 → 测试 → 给 AI 派任务 → 审查实际改动 → 团队协作 → 发布与质量。

[进入开发专题](docs/engineering/README.md) · 包含 METR、AGENTS.md、FixedBench、ImpossibleBench 的研究解读，以及完整 PR 审查练习。

### 04 · 软件测试：不只看一排绿色

怎样选输入 → 怎样覆盖组合 → 怎样检查条件 → 怎样理解覆盖率 → 怎样生成测试 → 怎样判断结果。

[进入测试专题](docs/testing/README.md) · 以 ISTQB、NIST、NASA 和软件测试经典论文为线索，最后用一条折扣规则贯通。

## 怎样读才有收获

**第一次接触**：从每个专题的导读开始，先掌握一个完整例子，再读公式。遇到陌生术语，先看它在例子中负责哪一步。

**正在做项目**：先明确当前最痛的失败，再找对应章节。不要把所有设计模式一次性塞进系统；先形成一个能检验的判断，例如“减少重复规划是否降低了总成本，同时保持任务完成率”。

**准备深入读论文**：保留原论文窗口，对照文中的页码、图表和实验条件。自测题中的算例用于理解机制，不等于重新跑过论文实验。
