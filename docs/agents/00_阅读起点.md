语言模型能生成一段答案；当任务需要查资料、调用工具、等待结果、发现失败并继续处理时，还需要安排这些动作发生的顺序，并保存足够的状态。这里讨论的 Agent 设计，主要就是怎样组织这一过程。九篇论文各自改变其中一部分，研究任务、模型、工具和评测方式并不相同。

“九种设计模式”是便于学习的组织名称，不是一套由九篇作者共同制定的、互斥且完整的标准分类。Plan-and-Solve 与 Self-Discover 有些实验只是组织一次推理，并不必然调用外部工具；Self-Refine 可以只修改文本；STORM 则针对调查写作。先保留这些差异，才不会把所有带步骤的提示都叫作同一种 Agent。

<a id="section-1"></a>
## 从三个具体困难进入论文

第一个困难是信息不够。模型可能知道该问什么，却不知道最新事实，或者需要先查询才能决定下一步。ReAct 把思考与行动交替起来，重点是观察如何改变后续动作。

第二个困难是过程组织不合适。简单题可能只需要明确计划；多个独立查询若串行等待，会浪费时间；每一步都重读全部历史，会花费很多上下文。Plan-and-Solve、ReWOO、LLMCompiler 分别从推理计划、计划与证据分离、依赖调度来处理这些问题。它们的共同词是“计划”，具体机制却不能互换。

第三个困难是第一遍结果不可靠。Self-Refine 给当前答案提修改意见；Reflexion 用上次任务尝试的反馈形成下一次尝试的记忆；LATS 把多个候选过程放进搜索树，按评价与访问情况分配尝试。它们都可能增加计算，但“多算几次”与“获得更可靠的新证据”是两回事。

最后两篇把视角向前移：Self-Discover 先选择和组织适合任务的推理方式，再解具体实例；STORM 先开展多角度调查并形成提纲，再写文章。这让我们从“怎么回答”回到“开始回答前，应先组织什么”。

<a id="section-2"></a>
## 九篇的研究主线

| 论文 | 核心对象 | 读完应能解释的技术问题 |
|---|---|---|
| ReAct | 思考、工具行动、观察的交替轨迹 | 观察怎样修正下一步，为什么某些纯推理任务仍需混合策略 |
| Plan-and-Solve | 零样本的计划与求解提示 | 计划减少哪类遗漏，额外指令为何也可能让某些题更差 |
| ReWOO | 带占位符的计划与证据汇总 | 哪些依赖可预先表达，哪些新信息会迫使重新计划 |
| LLMCompiler | 带依赖的工具任务图 | 并行、流式下发与关键路径怎样决定延迟 |
| Self-Refine | 当前答案和具体修改意见 | 反馈从哪里来，停止和答案选择为何影响结果 |
| Reflexion | 尝试之间保留的文字反思 | 测试信号真假怎样影响记忆，累计成功率与一次提交有何区别 |
| LATS | 候选轨迹树及其价值估计 | 选择、扩展、模拟、回传怎样分配搜索预算 |
| Self-Discover | 可复用的任务推理结构 | 结构选择与实际执行的错误怎样分开，准备成本如何摊销 |
| STORM | 调查问题、来源集合与提纲 | 多角度追问怎样影响信息覆盖，为何有引用仍会产生错误关系 |

建议第一轮按章节顺序读，最后做综合章的情境练习。第二轮可以把 ReAct 与 ReWOO 对读，讨论“何时必须先观察”；把 Self-Refine、Reflexion 与 LATS 对读，讨论“改进信号来自哪里”；把 Self-Discover 与 STORM 对读，讨论“先设计过程”的对象究竟是推理结构还是调查问题。对读不能代替逐篇阅读，因为它们的实验条件不相同。

<a id="section-3"></a>
## 先掌握四个会反复出现的区分

**文字状态与模型参数不同。** 保存历史、反思或提纲，只是改变下一次输入；只要没有训练步骤，不能叫作模型权重学会了这个任务。ReAct、ReWOO 等论文还包含专门的训练或迁移实验，章内会与提示方法分别解释。

**外部观察与自我评价不同。** 工具返回网页、程序测试失败、环境给出奖励，与模型自己说“我觉得这一步不错”，具有不同的证据来源。外部信号也可能错误或不完整，但不能把两者一概叫作反馈而忽略可靠性。

**一次最终答案与一次内部尝试不同。** pass@1 通常描述最终提交一个候选的结果；这个候选可能已经经过多轮生成、测试或搜索。因此，看到 pass@1 就假定只调用模型一次，会误读成本。允许重试到成功的累计成功率又是另一个量。

**更高得分与更高效率不同。** 一个方法可能多用十倍查询提高成功率，也可能在同一质量下减少等待。比较时至少读清成功率、时间、tokens、工具调用、候选数量及失败请求的成本，不能只挑最有利的一个轴。

<a id="section-4"></a>
## 资料版本与证据边界

每章依据各章标注的原文版本，列出主要方法、原例、公式、实验条件、重要结果、负结果与局限。对于作者声称的首次贡献或被引工作的结论，未独立追读时会保留归属。没有把旧版本结果改写成当前模型或框架的能力；也没有为本教材运行付费模型调用、训练或复现实验。

各章中的教学推导与自测用于暴露理解缺口。例如，计算流式调度完成时间、重算百分点、追踪测试误判如何污染反思，都可以只靠原文定义进行。它们不等于重新取得论文实验结果。来源页保留原始 PDF、版本、页数及文件指纹，以便你核对同一份材料。

阅读时不要只问“这个模式适合什么场景”。还应问：它改变了原流程的哪一个变量？成功依赖哪些可用信号？消融实验排除了什么解释？如果对照获得同样的计算预算，结论还会怎样？研究者的阅读习惯，正是在这些可检查的问题上形成的。
