## 研究问题：找到资料，与根据资料做对下一步，是两件事

一个助手被问到某个软件可以由什么设备控制。它可能完全依靠记忆，把相关产品混为一谈；也可能已经查到正确资料，却没有将资料转换成问题需要的答案。前一种错误发生在事实来源，后一种发生在证据使用。ReAct 研究的正是二者的连接：**模型能否一边整理当前任务，一边与外部环境交互，让分析和行动互相纠正？**

在这篇论文之前，让模型先写中间解题过程再回答的方法已经出现，这类方法称为思维链，英文缩写 CoT。它能把复杂问题展开，却不自动获得新事实。如果第一步误认一个实体，后面推得再顺，仍可能得到错误答案。另一类研究已经让模型搜索网页或控制机器人，例如 WebGPT、SayCan 和 Inner Monologue。它们证明了语言模型可以参与行动选择，但作者认为，仅有行动和环境状态反馈，还不足以灵活表达目标分解、进度判断、常识推断和异常处理。[引言与相关工作，PDF 第 1–3、9 页](https://arxiv.org/pdf/2210.03629v3#page=2)

因此，ReAct 的贡献不是“首次出现能够用工具的智能体”，也不是“最早有环境反馈”。它把自由语言分析与外部动作放进同一条任务轨迹，并用两组问题检验这个设计：知识问答中，外部行动能否改善推理；交互决策中，推理能否改善行动。前一组要问“信息够不够、能否推出答案”，后一组要问“目标做到哪了、接下来该做什么”。两组实验合起来，才对应论文标题里的“协同”。

这里关于前作差别的定位来自本论文的相关工作；本章没有逐篇复核所有更早的原始研究，因此不把作者的首创性措辞当作独立认证的历史结论。

## 先走一遍原论文的问答轨迹

图 1 的问题是：除了 Apple Remote，还有什么设备能控制它最初设计用于交互的程序？直接回答的模型猜了 iPod。只使用内部推理的模型则先认定那个程序是 Apple TV，然后把能控制 Apple TV 的其他设备当作答案。它的问题不是没有写步骤，而是第一步事实就错了。

ReAct 首先搜索 Apple Remote，外部返回的信息指出，原先控制的是 Front Row 媒体中心程序。模型随后把“要找的程序已确定”写进分析，下一步搜索 Front Row。这个搜索没有找到准确页面，却返回相近实体，其中包含 Front Row 的软件页面。于是模型修改查询，搜索 `Front Row (software)`，最后从页面中找到 keyboard function keys，也就是键盘功能键，完成回答。[图 1，PDF 第 2 页](https://arxiv.org/pdf/2210.03629v3#page=2)

这一小段过程包含三个不同的转换。第一次检索修正了内部记忆；第一次失败的搜索触发了查询改写；最后的分析把资料中“还能用什么控制程序”提取成答案。外部返回值称为 Observation，模型发出的工具请求称为 Action，写在二者之间的分析称为 Thought。观察来自环境，不能由模型自己续写一段看似真实的检索结果来替代。

同一图中的只行动基线也找到了正确的软件页面，最后却回答 `yes`。这使对照更有价值：它不只是说明“有搜索比没搜索好”，还说明找到证据之后，仍需要把证据与原问题联系起来。ReAct 增加的语言分析，正是为了帮助完成这种联系。

原论文的工具比今天许多搜索助手简单。`search[entity]` 找到实体页时返回前五句；找不到时返回五个相近实体。`lookup[string]` 在当前页面里寻找下一个包含指定字符串的句子，类似页面内查找。`finish[answer]` 则结束任务。作者明确指出，这种接口弱于先进的专用检索器；选择它，是为了让模型必须通过明确的语言推理安排检索。所以这里的效果同时受工具接口限制，不能把所有失败都归因于推理，也不能把结果直接迁移到任何搜索系统。[§3.1，PDF 第 4 页](https://arxiv.org/pdf/2210.03629v3#page=4)

## 原始形式化：为什么把分析也看作一种动作

先把交互过程写清楚。第 t 步，环境给出观察 oₜ，模型看到此前所有观察和动作，形成上下文 cₜ。根据上下文选择下一动作的规则，称为策略 π。原文的形式化是：

```text
cₜ = (o₁, a₁, …, oₜ₋₁, aₜ₋₁, oₜ)
aₜ ∈ A，按 π(aₜ | cₜ) 选择
```

cₜ 是一串历史记录；aₜ 是一个可执行动作；π(aₜ | cₜ) 表示在这段记录已知时选择某动作的条件概率。它们不是必须具有相同长度的数值向量。普通行动模型需要直接从整个历史跳到下一动作，例如在几十个柜子里找东西时，直接判断接下来去哪。这种映射可能很难，因为当前记录并未显式总结哪些子目标已经完成。

ReAct 的做法是允许模型暂时不改变环境，先写一段有用的分析。设 A 为外部动作集合，L 为可以生成的语言集合，原文将允许输出的集合扩展为：

```text
Â = A ∪ L
若 âₜ ∈ L，则 cₜ₊₁ = (cₜ, âₜ)
```

集合符号 ∪ 表示合并可选项。当输出属于语言空间时，只扩充上下文，不改变外部状态，也没有新环境证据。例如“刚才没有找到完整名称，应使用候选的软件实体名”可以改变下一次动作，却不能凭这句话就让检索成功。若输出属于外部动作空间，执行器才真正调用工具并把新观察带回来。[§2，PDF 第 3 页](https://arxiv.org/pdf/2210.03629v3#page=3)

这条形式化说明了方法如何组织信息，却没有证明增加分析一定更好。更大的输出空间也更难学习，模型可能生成错误分析、无效计划或重复动作。作者依赖预训练大模型已有的语言能力，再给少量人工轨迹示范来诱导这种行为；主实验没有为此重新训练一个专门模型。

还要注意“交替”不意味着每一个动作之前都必须写一段分析。在问答中，作者使用较密集的分析—行动—观察循环；在需要几十步移动的交互任务中，分析只在有用的位置出现，例如找到物品、切换子目标或处理异常时。这样，分析承担的是状态整理，不是为每次动作机械增加文字。[§2，PDF 第 3–4 页](https://arxiv.org/pdf/2210.03629v3#page=3)

## 知识实验：单独 ReAct 并非最好的全部答案

知识实验用 PaLM-540B。HotpotQA 要结合多个资料回答问题，提示含六个示范；FEVER 判断陈述被支持、被反驳或证据不足，提示含三个示范。两者都只给问题或陈述，不预先提供支持段落，因此模型必须使用内部知识或自行检索。

HotpotQA 使用答案完全匹配比例，简称 EM；只要最终文本与标签不匹配，就可能记错，即使含义接近。FEVER 使用分类准确率。它们评价的不是推理过程是否忠实，也不是系统在现实任务中的全面可靠性。所读正文未明确确认主表的具体评测题数；附录 GPT-3 对照的 500 题不能移作主表分母。[§3.1–3.3、表 1，PDF 第 4–6 页](https://arxiv.org/pdf/2210.03629v3#page=5)

| 提示方法 | HotpotQA EM % | FEVER 准确率 % |
|---|---:|---:|
| 直接回答 Standard | 28.7 | 57.1 |
| 只推理 CoT | 29.4 | 56.3 |
| CoT 多次采样后投票 | 33.4 | 60.4 |
| 只行动 Act | 25.7 | 58.9 |
| ReAct | 27.4 | 60.9 |
| CoT 投票不足时转 ReAct | 34.2 | 64.6 |
| ReAct 未完成时转 CoT 投票 | 35.1 | 62.0 |

先看控制较直接的一组：ReAct 相对 Act 在两任务提高 1.7、2.0 个百分点，支持“在行动轨迹中增加分析有帮助”。但 HotpotQA 的 ReAct 又比 CoT 低 2.0 个百分点。因此不能从这张表得到“访问外部知识后推理必然更准”的结论。

作者进一步利用二者的互补性。多次采样得到多条推理答案，再选出现最多的答案，这种做法称为自一致性，文中记为 CoT-SC。主表用温度 0.7 生成 21 条推理链。温度控制生成的随机性，采样链数则直接增加推理预算。

第一种混合策略先运行 ReAct；如果 HotpotQA 七步内、FEVER 五步内没有结束，就改用 CoT-SC。第二种先运行 CoT-SC；如果最高频答案出现次数少于总样本数的一半，便认为内部知识可能不够确定，改用 ReAct。这是启发式路由，投票集中并不等于正确概率已经得到校准。主表最好的提示成绩分别来自两种混合方式，说明论文真正支持的是按条件结合内部与外部知识，而不是只保留一种固定流程。[混合策略与图 2，PDF 第 5–6 页](https://arxiv.org/pdf/2210.03629v3#page=5)

图 2 还显示，混合方案用三到五条 CoT 样本就能达到纯 CoT-SC 用 21 条样本的相近表现。不过检索和 ReAct 调用仍要消耗资源，所以“少采样几条”不能直接换算成总成本节省多少。

## 错误分析：答对不等于走对，接入证据也不等于不幻觉

作者从 ReAct 和 CoT 分别抽取 50 条正确、50 条错误轨迹，共 200 条，人工判断行为类型。在答案正确的子样本中，ReAct 有 6% 轨迹仍含错误推理或事实，CoT 为 14%。这些叫假阳性：评分通过了，过程却没有真正支持结论。

原文附录给了一个很鲜明的例子：问题比较两个桌游 San Marco 和 About Time 的发行顺序，ReAct 却把前者查成威尼斯城区、后者理解成电影，最后碰巧输出正确的桌游名字。只看最终 EM 就会错把这段轨迹当成可靠推理。[表 2，PDF 第 6 页；失败分析，PDF 第 32 页](https://arxiv.org/pdf/2210.03629v3#page=32)

在错误子样本中，ReAct 的推理错误、搜索结果错误、幻觉、标签歧义分别为 47%、23%、0%、29%；CoT 的推理错误、幻觉、标签歧义为 16%、56%、28%。这里按原表保留比例，文中没有逐项原始人数供完整回算。尤其“幻觉 0%”只描述这个失败子样本，并非全测试集无幻觉，更不是普遍保证。

这组对照揭示了一个取舍。外部证据减少凭记忆编造事实，但检索不到有用内容时，ReAct 容易重复旧查询，或被固定的交替结构束缚，不能灵活地展开推理。作者把循环也归入推理错误，并怀疑逐次选择最高概率输出的解码方式可能有影响；这是作者解释，尚没有对应消融证实。

另一个限制来自标签本身。图 4 展示酒店房间数的旧标签与当时网页信息不同，提示实时检索结果不一定与静态测试答案一致。这说明评价需要时间口径，但该个案并不能证明所有不匹配都是模型对、标签错。本章也没有把其中的房间数量当作今天的实时事实。[§3.3，PDF 第 6 页；图 4，PDF 第 14 页](https://arxiv.org/pdf/2210.03629v3#page=14)

## 交互任务：分析怎样保存行动的前提

现在把问题从“答对一个名字”换成“把一把洗净的刀放在台面”。原文的文字家居环境 ALFWorld 中，模型必须通过移动、拿取、清洗、放置等动作完成目标。它看不到所有物品的位置，只能逐处检查；某些任务可包含五十多个位置，并需要五十多步才能完成。

ReAct 的原始轨迹先分清“找刀—拿刀—去水槽—清洗—放到台面”。找到并拿起刀后，它写明当前已完成拿取，下一步要去水槽，于是移动后再清洗。Act-only 也找到了刀，却仍站在台面前就调用清洗；环境返回没有效果之后，又去拿另一把刀，随后反复循环。这里分析的作用不是增加关于刀的知识，而是把“我已经拿到什么”和“清洗需要先到哪里”连接起来。[附录 D.2，PDF 第 28–30 页](https://arxiv.org/pdf/2210.03629v3#page=28)

实验使用 134 个未见任务。每类任务先标注三条训练轨迹，从中选择两条并排列，形成六组提示。Act 使用同样动作轨迹，但去掉分析，因此能较好地控制示范任务差异。需要严格区分六组提示的平均表现与其中最好一组：

| ALFWorld 方法 | 表中总体成功率 % | 统计口径 |
|---|---:|---|
| ReAct | 57 | 六组提示平均 |
| ReAct | 71 | 六组提示中的最好结果 |
| Act | 45 | 六组提示中的最好结果 |
| ReAct-IM | 48 | 六组提示平均 |
| ReAct-IM | 53 | 六组提示中的最好结果 |
| BUTLER | 37 | 原基线八次试次中的最好结果 |

摘要中“提高 34%”对应 71−37，即 34 个百分点，不能写成任意一次使用的平均收益。ReAct 最差提示组仍有 48%，高于 Act 的最好 45%，这为结果对提示选择的稳定性提供了更有价值的补充。[§4、表 3，PDF 第 7–8 页](https://arxiv.org/pdf/2210.03629v3#page=8)

ReAct-IM 是作者把同一专家轨迹重新标成类似 Inner Monologue 的密集状态反馈，不是完整复现机器人系统。它限制了调用常识、确认子目标完成和切换下一目标的分析，整体比 ReAct 弱；但清洗子类的最好成绩反而是 68% 对 58%，所以不能写“所有类型均更好”。这个消融同时改变内容与分析频率，也不能单独证明稀疏分析必胜密集分析。

WebShop 则模拟商品选择，含真实商品文本和选项，但实验中的“购买”是基准环境行为。500 条测试指令中，ReAct 成功率为 40.0%，Act 为 30.1%，模仿学习基线为 29.1%，模仿加强化学习为 28.7%；人类专家为 59.6%。成功率要求选定商品满足全部需求，平均属性得分则分别是 66.6、62.3、59.9、62.4、82.1，两种指标不能互换。ReAct 能利用分析检查口味、包装数量等选项，却仍明显落后于更善于继续探索和改写查询的人类。[表 4、原始购物轨迹，PDF 第 8、31 页](https://arxiv.org/pdf/2210.03629v3#page=31)

## 微调和人工纠偏告诉我们，提示实验之外还有什么

论文也发现，小模型不一定能仅凭少量示范学会这种复杂轨迹。在 PaLM-8B/62B 上，少样本 ReAct 提示表现很弱；作者从大模型输出中筛出最终答案正确的 3000 条轨迹进行参数训练后，ReAct 变成比较中表现最好的方式。这里调整已有模型参数的过程称为微调，它与前面冻结模型的提示实验不同。[图 3，PDF 第 6–7 页](https://arxiv.org/pdf/2210.03629v3#page=7)

不过训练比较也有条件：Act/ReAct 训练 4000 步；Standard/CoT 在 8B 用 2000 步，在 62B 用 1000 步，因为作者观察到继续训练会退化。它支持经过调整的训练方案有效，不能据此说固定训练算力后单靠轨迹格式就一定赢。筛选标准还是最终答案正确，前面假阳性例子也提醒我们，这不自动保证每条训练轨迹的推理都正确。[附录 B.1，PDF 第 15 页](https://arxiv.org/pdf/2210.03629v3#page=15)

人工干预实验进一步展示了语言记录的可操作性。模型错误地相信第二把钥匙还在同一个抽屉，后续行动因此反复失败；人类删除这一错误判断，再提示其他可能位置，轨迹转而成功。这说明语言记录提供了一个方便的行为干预接口。它只是示范案例，尚没有系统性的人类实验，也不能证明这些文字忠实揭示了模型内部全部因果过程。[图 5，PDF 第 14–15 页](https://arxiv.org/pdf/2210.03629v3#page=15)

## 怎样形成自己的研究判断

这篇论文最强的证据是：在这些模型、提示和环境接口下，加入明确分析能够改善只行动的系统；在知识任务上，内部推理与外部检索的混合又能进一步改善结果。它的限制也很具体：搜索质量影响推理，分析可能错误，反馈可能触发循环，最终答案指标可能掩盖过程失真。

一个可检验的后续问题是：改进主要来自分析真的保存了任务状态，还是只因为多生成了一段文字？可以固定模型、动作预算和文本长度，比较真实状态摘要、等长无关文字、只复述目标，以及明确区分“已完成／待完成”的记录。若状态组织是关键，最后一种应更稳定地减少重复动作和遗漏前提；若只增加文字也获得同样收益，对机制的解释就需收窄。这个方案只是研究提议，本次没有运行模型验证。

## 自测与答案

**问题一：模型搜索失败后又写了一段分析，这算获得了新证据吗？** 不算。分析只更新上下文；只有新的外部动作及其返回结果才可能增加外部证据。分析的价值在于改变下一次查询或承认缺口。

**问题二：为什么不能用 71% 概括 ALFWorld 的平均成功率？** 因为 71% 是六组提示的最好结果，平均为 57%。选择最好结果与平均部署表现回答的是不同问题。

**问题三：若一次回答匹配标签，是否就能把轨迹作为可靠示范？** 不能。桌游被误查成城区和电影的例子表明，答案可能碰巧正确。还需检查中间事实、实体对应及结论是否由证据支持。
