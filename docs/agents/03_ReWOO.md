## 研究起点：每次拿到结果，都需要重新请模型规划吗

问一个人的导师出生在哪里，第一步要查导师是谁，第二步才知道具体该查哪个人的出生地。但是在第一步结果到来之前，我们已经知道第二步要做的事。未知的是姓名这个值，不是“用姓名查询出生地”这条关系。

ReWOO 抓住了这种区别。ReAct 通常在每次工具返回后，把问题、规则、示范、此前分析和全部观察再次交给模型，让它决定下一步。这种方式很适合真正需要随时改变方向的任务，却也会反复输入大量相同文字。若未来步骤只是把一个未知值填到已知位置，反复启动主模型规划就可能不必要。

论文把提前组织这些关系的能力称为 foreseeable reasoning，可理解为对后续处理方式的预先安排。标题中的“Without Observation”指规划过程不等待每一步真实观察，**不是整个系统不要观察，更不是允许模型编造工具结果**。观察仍然进入工具执行和最终回答，只是暂时不回到主规划过程。[引言、§2.1，PDF 第 1–4 页](https://arxiv.org/pdf/2305.18323v1#page=3)

这是一项系统组织方法。它一方面减少工具增强模型的提示重复，另一方面让规划单独成为可训练模块。与之最直接的前作是 ReAct：两者都使用工具，但不同意每个工具结果都必须立即影响下一段主推理。另一条相关路线是训练模型使用工具，论文讨论了 Toolformer 与工具轨迹微调，并提出把较通用的规划能力从大模型转移给小模型。后者是独立贡献，不能只用“省 token”一句带过。

<a id="section-2"></a>
## 从酒庄问题看见变量怎样连接未知结果

图 1 的原问题是：制作 The Hennchata 主要成分的干邑酒庄叫什么？系统先安排需要取得哪些证据，然后执行，最后回答。负责安排步骤的角色叫 Planner，负责调用工具的角色叫 Worker，负责综合计划与证据的角色叫 Solver。它们是功能划分，不意味着一定有三个不同模型。

Planner 一次写出四个步骤。第一步查 The Hennchata，把结果保存为 `#E1`；第二步让一个语言模型工具根据 `#E1` 提取主要成分，保存为 `#E2`；第三步以 `#E2` 为查询词检索百科，得到 `#E3`；第四步根据 `#E3` 判断生产 `#E2` 的酒庄，得到 `#E4`。这时 E1 到 E4 都只是未来结果的引用位置。[图 1、§2.1，PDF 第 2–3 页](https://arxiv.org/pdf/2305.18323v1#page=2)

Worker 运行后，E1 变成一段介绍饮品的真实返回文字，里面出现 Hennessy cognac。E2 的输入原先包含 `#E1`，现在替换为那段文字，模型工具提取出 Hennessy cognac。接着 E3 实际查询这个名称，E4 根据新页面提取 Jas Hennessy & Co.。最后，Solver 看到原问题及每个计划与证据的配对，给出答案。

这个过程值得慢慢读两遍。第一次关注值的流动：每个引用都必须在前一个结果实际出现后替换。第二次关注主模型是否被打断：Planner 一开始并不知道 Hennessy，却仍能完整写出“先找成分，再找成分生产者”。未知值并没有妨碍它安排已知的处理关系。

原例四步之间都有依赖，因此工具仍要逐步执行。ReWOO 节省的主要是反复规划和重读提示，不是这个例子突然变成四路并行。论文把图优化与并发作为后续方向之一；不能因为出现了依赖引用，就把后来完整的并行调度能力自动算到这个版本头上。

还要数清模型调用。主要 Planner 一次、Solver 一次，但第二步和第四步本身就是模型工具。因此这个原例不是“总共只调用两次模型”。Worker 也不等于可靠的确定性计算程序：它既可能调用百科，也可能调用另一个语言模型，后者仍可能误读或编造内容。[工具设置，PDF 第 6 页](https://arxiv.org/pdf/2305.18323v1#page=6)

<a id="section-3"></a>
## 最终回答者为什么仍然需要推理

如果所有证据都已经填好，为什么不直接返回最后一个变量？因为工具结果可能很长，计划也可能不完美。Solver 需要判断哪段真正回答了问题，忽略无关内容，有时还要比较多个证据或补做简单推断。

原文明确说，提醒 Solver 谨慎使用证据有助于表现，作者把原因归于它能够补偿部分规划或工具失败。但这同时给评价带来一个重要问题：如果所有工具都失败，Solver 仍可能从模型记忆里答对。这样的结果表明系统保留了内部知识，不代表它在没有证据时完成了有根据的检索问答。[§2.1、Solver 提示，PDF 第 4、14 页](https://arxiv.org/pdf/2305.18323v1#page=14)

因此系统中的 Evidence 只是“工具返回内容”这个数据角色，不应理解为“已经验证过的事实”。尤其经过语言模型工具加工的结果，与最初原始资料之间已经隔了一层解释。变量替换能保证后一步拿到前一步的字符串，却不能保证这个字符串忠实于原始来源。

<a id="section-4"></a>
## 成本公式第一步：把反复输入的次数数出来

理解论文的节省量，要先区分模型读入的文本量、模型生成的文本量、工具费用和真实等待时间。原文的两条核心公式只分析主模型的输入 token。token 是模型处理文字的计数单位，不等于汉字数，也不直接等于一次请求的总费用。

设 C 为固定说明，S 为示范，Q 为用户问题。原文用 Θ(p) 表示文本 p 的 token 数；这里的 Θ 是作者自定义的长度符号，不是算法复杂度中的渐近记号。第 j 步产生的分析、动作、观察分别是 Tⱼ、Aⱼ、Oⱼ。为看清求和，先将固定包长度记为 B，将一段历史长度记为 hⱼ：

```text
B = Θ(C + S + Q)
hⱼ = Θ(Tⱼ + Aⱼ + Oⱼ)
```

加号表示文本拼接。假定总共调用主模型 k 次，每次都发送完整累积历史。那么各次输入长度依次是 B、B+h₁、B+h₁+h₂，直到最后的 B+h₁+…+hₖ₋₁。把它们相加，固定包被发送 k 次；第一段历史被之后 k−1 次调用重读，第二段被重读 k−2 次，于是得到论文式（1）：

```text
I_TAO = k·Θ(C+S+Q)
　+ Σⱼ₌₁ᵏ⁻¹ (k−j)·Θ(Tⱼ+Aⱼ+Oⱼ)
```

这一步是对同一批重复输入换一种计数方式。若历史块长度都约为 h，历史项等于 `h×[1+2+…+(k−1)] = h·k(k−1)/2`，随步数近似平方增长。固定说明和示范项则只随 k 线性增长。也就是说，二次增长来自“早期历史在后续反复出现”，不能只因为固定提示很长就说它本身二次增长。[§2.2、式（1），PDF 第 4 页](https://arxiv.org/pdf/2305.18323v1#page=4)

这个结论带有明确前提：完整历史每次重发，没有截断、压缩或改变计费口径的缓存。它是提示长度模型，不是对实际服务器浮点运算量或耗时的直接证明。真实分词在拼接边界也可能有细小差别；这里按文本块近似可加来理解，已经足以说明重复的来源。

<a id="section-5"></a>
## 第二步：哪些材料只需要读一次

ReWOO 给 Planner 的第一包是角色说明、示范与问题；给 Solver 的第二包是角色说明、问题和全部计划证据。记 Cₚ、Cₛ 为两者说明，第 j 步计划和真实证据为 Pⱼ、Eⱼ，论文式（2）为：

```text
I_ReWOO = Θ(Cₚ+S+Q)
　+ Θ(Cₛ+Q+Σⱼ₌₁ᵏ(Pⱼ+Eⱼ))
```

若两角色说明长度都近似 C，则可近似展开为：

```text
I_ReWOO ≈ 2Θ(Q)+2Θ(C)+Θ(S)
　+ Σⱼ₌₁ᵏ Θ(Pⱼ+Eⱼ)
```

问题出现两次，两个角色各有说明；示范只给 Planner 一次；每份计划和证据在最后汇总时出现一次。它们不用再被之后每次主规划调用重读。如果每个计划证据块长度大致稳定，总量便更接近随步骤线性增长。[式（2），PDF 第 4 页](https://arxiv.org/pdf/2305.18323v1#page=4)

做一个教学算例：固定包 1000 token，四次逐步调用，每步历史块 200 token，输入总量为 `4×1000+200×(3+2+1)=5200`。假设 ReWOO 两个主输入的固定部分各 1000、四份计划证据共 800，则为 2800。这个假设例子只核验计数关系，没有包含输出、模型工具、缓存折扣和网络等待，也不是作者实验。

它还有一个简单的边界：如果题目只需一步，额外安排 Planner 与 Solver 可能增加开销。若原方法已经有效压缩历史，差距也会变小。论文自己说明，在不知道具体提示和步骤长度时，不能从两条式子直接推出一个固定节省倍数。

附录的 token 分解进一步表明，HotpotQA 的实际收益还来自示范更短。ReAct 示范包含观察，百科返回可能很长；ReWOO 规划示范不含这些观察。于是五倍左右的差异既包括“少重复”，也包括“每次发的材料更短”。要把收益全部归给取消逐步观察，就还需要控制示范长度的比较。[附录 A.1、图 7，PDF 第 12 页](https://arxiv.org/pdf/2305.18323v1#page=12)

## 主实验：省了多少，以及“更准确”是哪一种准确

主表使用 gpt-3.5-turbo，但本地版本未给稳定的服务端快照编号。HotpotQA、TriviaQA、GSM8K 各 1000 题，StrategyQA 和 SportsUnderstanding 各 300，PhysicsQA 53。SOTUQA 是作者围绕 2023 年国情咨文构造的任务，表内没有明确题数，不能从百分比反推分母。

HotpotQA 用六个同任务示范，TriviaQA、GSM8K 各一个；其他任务给一个任务外示范。作者把后者视为零样本迁移，但它并非完全没有格式示范。ReAct 与 ReWOO 使用对应的示范问题和工具集合，轨迹格式则按各自方法改写。[实验设置，PDF 第 5–7 页](https://arxiv.org/pdf/2305.18323v1#page=6)

| 数据集 | 题数 | ReAct Acc % | ReWOO Acc % | 每题 token：ReAct → ReWOO |
|---|---:|---:|---:|---|
| HotpotQA | 1000 | 40.8 | 42.4 | 9795.1 → 1986.2 |
| TriviaQA | 1000 | 59.4 | 66.6 | 4212.9 → 1340.9 |
| GSM8K | 1000 | 62.0 | 62.4 | 1874.3 → 1089.3 |
| StrategyQA | 300 | 64.6 | 66.6 | 1686.3 → 1287.1 |
| PhysicsQA | 53 | 64.1 | 66.0 | 2163.3 → 1225.7 |
| SportsUnderstanding | 300 | 58.6 | 61.3 | 1720.0 → 854.2 |
| SOTUQA | 未明确 | 64.8 | 70.2 | 1840.3 → 1048.8 |

这里的 Acc 由 GPT-4 判断语义答案是否正确。论文还报告答案精确匹配 EM，以及文中称为字符级的 F1 重合指标。三者有不同用途：含义相同但写法不同可能过不了 EM；模型语义判分能放宽这种限制，却引入判断模型自己的误差。表中 token 包含模型工具消耗，与前面只分析主输入的公式不是完全同一个统计边界。[指标与表 2，PDF 第 6–7 页](https://arxiv.org/pdf/2305.18323v1#page=7)

HotpotQA 的 token 比为 9795.1÷1986.2≈4.93，即减少约 79.72%；Acc 提高 1.6 个百分点，相对原值提高约 3.92%。这才是摘要“约五倍效率、约 4% 准确率改善”可以对应的精确解释。与此同时，EM 从 32.2 降到 30.4，F1 从 39.6 升到 40.1。不能只挑语义分数上涨就写成所有质量指标都提高。

其他负结果同样重要。TriviaQA 的直接回答 Acc 是 80.6，高于 ReWOO 的 66.6；GSM8K 的 CoT 为 67.4，高于 62.4；SportsUnderstanding 的直接回答为 68.0，高于 61.3。工具让系统获得能力，也可能让它绕路、误用返回内容或被无关结果干扰。这张表支持“ReWOO 优于该实验中的 ReAct”，并不支持“每个任务都应使用工具”。

## 原文数值的几处不一致，应当怎样处理

按六个公开数据集的表 2 等权平均，ReAct Acc 为 58.25，ReWOO 为 60.88，增加约 2.63 个百分点，相对增加约 4.52%。正文却称为“absolute accuracy gain of 4.4%”。同样，SOTUQA 的 64.8→70.2 是增加 5.4 个百分点、相对约 8.33%，正文却写成 8% 的绝对准确率提高。

这些差异不能用翻译模糊掉。本章按表格重新计算，保留“百分点”和“相对百分比”的区别，不把正文措辞悄悄改成一条没有问题的原结论。六集 token 均值减少约 63.72%，则能对应正文约 64% 的概括。[§3.2、表 2，PDF 第 6–7 页](https://arxiv.org/pdf/2305.18323v1#page=6)

费用表还有一处局部冲突：同为 9795.1 token，表 2 写 ReAct 每千题 19.59 美元，表 3 的正常行写 21.29。本章不猜测其来源，也不把这个费用当作当前价格。报告不一致降低对应数字的可复核性，但不自动推翻其他能由表内数据核验的 token 比较。[表 3，PDF 第 8 页](https://arxiv.org/pdf/2305.18323v1#page=8)

## 工具失效之后，完整计划有什么优势，又有什么代价

作者强制所有工具返回没有证据的固定消息。ReAct Acc 从 40.8 降到 0，ReWOO 从 42.4 降到 13.2；token 变化分别为增加 851.1、减少 110.8。这个试验说明，ReWOO 比较不容易因为连续失败观察陷入无效循环，而且最后的 Solver 仍保留少量内部知识答题能力。

但 13.2% 仍远低于正常状态，更不表示工具失败时可靠。这个测试只覆盖“全部明确没有结果”，没有涵盖半真半假的返回、限流、部分步骤失败等情况。系统是否能识别自己在凭记忆回答，也没有由该分数证明。[工具失败试验，PDF 第 7–8 页](https://arxiv.org/pdf/2305.18323v1#page=8)

另一个试验逐步增加工具。加入 Google 曾提高表现，继续加入计算、餐厅、文档、社交搜索等工具后，整体趋势下降。作者检查 20 个“两工具设置答对、七工具设置答错”的案例，17 个存在工具误用，例如用餐厅搜索查询名人。这是经过条件筛选的失败子集，不能说所有任务中 85% 都会误用工具。图 5 起点标签写 “No tools”，而正文说明从原有工具设置增添工具，因此不能将该点解读为完全不使用工具的 ReWOO。[图 5，PDF 第 7–8 页](https://arxiv.org/pdf/2305.18323v1#page=8)

更细的错误分析对每种方法各抽 100 条失败轨迹，允许一条轨迹带多个标签：

| 失败标签 | ReAct | ReWOO |
|---|---:|---:|
| 推理方向错误 | 76 | 51 |
| 工具未取得有效信息 | 20 | 29 |
| 超过 token 限制 | 18 | 0 |
| 证据已足够但答案综合错误 | 3 | 11 |
| 问题或标签有歧义 | 17 | 17 |

因为可以多标签，列总数超过 100 并不矛盾。ReWOO 降低了循环和长历史问题，却更容易遇到“计划假定能取得某信息，工具实际上没有给出”的情况。例如它安排先查百科，再从返回里提取年龄，然而页面没有年龄；计划格式正确，信息前提却未满足。最终综合错误也没有因模块分工自动消失。[附录 A.2，PDF 第 12–13 页](https://arxiv.org/pdf/2305.18323v1#page=12)

原文 SOTUQA 示例甚至直接展示了后一种失败：原始材料明确写 Schumer 为 Senate Majority Leader，中间语言模型工具却把 Schumer 与 McConnell 的多数党／少数党职位对调，最后 Solver 又照抄了错误结果。同一轨迹内就能看到证据与结论冲突，无须诉诸当前政治事实。这说明“有真实检索”“有引用变量”“有最终总结”三件事同时成立，也可能仍然误读来源。[附录 C.7，PDF 第 21–23 页](https://arxiv.org/pdf/2305.18323v1#page=22)

<a id="section-9"></a>
## 将规划能力交给 7B 模型：模块化带来的第二项机会

规划时不接触实际观察，还有一个训练上的便利：可以把问题到规划蓝图单独当成学习任务，不必让小模型同时学习长工具返回和最终回答。作者用 text-davinci-003 为 HotpotQA、TriviaQA 混合训练题生成 4000 份蓝图，再保留最终答对的约 2000 份作为规划指令数据。

起点是已经通过 52k 自生成指令数据训练的 Alpaca 7B。作者继续训练这个七十亿参数模型，得到专门生成规划的 Planner 7B；采用只训练较小附加参数的 LoRA 方法，使实验可在单张 RTX 4090 上进行。附录给出 batch size 128、学习率 1e−4、输入截断长度 1024、LoRA rank 8、十轮训练。这些是作者的配方，本章没有实施训练。[§2.3、附录 B.1，PDF 第 4–5、13 页](https://arxiv.org/pdf/2305.18323v1#page=13)

图 6 比较的是更换 Planner 后的系统表现，不是把所有模型角色及工具都换成 7B。专门训练后部分任务优于普通 Alpaca，TriviaQA 表现较好；GSM8K 则明显低于 GPT-3.5。图中没有逐柱精确数值，因此本章不从柱高编造小数成绩。作者以 175B/7B≈25 来描述规模差，这也不能转换成整个系统参数、费用或耗时缩小二十五倍的结论。[图 6，PDF 第 8 页](https://arxiv.org/pdf/2305.18323v1#page=8)

作者还观察到，训练规划主要使用 Wikipedia 与 LLM 工具，推理时给新工具说明后，小规划器能一定程度使用 Google 和 Calculator。这为“学到的是较通用的任务分解，而非死记某几个工具调用”提供线索，但只有定性观察，尚不足以证明任意新工具都能可靠迁移。

<a id="section-10"></a>
## 方法边界：能预先安排用途，不等于能预先安排所有分支

论文自己用 ALFWorld 的找花瓶任务解释限制。只知道房间有许多柜子，却不知道花瓶在哪，规划器若完全不看中间观察，就可能只能把所有可能位置都列一遍。ReAct 可以在找到后立即停止搜索；完整预先计划则可能付出接近最坏情况的工作量。未知数值可以引用，未知执行方向却未必能由一个占位符解决。[限制与未来工作，PDF 第 8–9 页](https://arxiv.org/pdf/2305.18323v1#page=8)

另一个应收窄的解释是模型替换试验。作者将 gpt-3.5-turbo 换成 text-davinci-003，看到表现改善，并推测对话训练影响推理。然而两个服务模型的差别不只一个训练环节，实验不能独立证明某种训练方法导致退化。可以报告模型替换现象，不宜把作者的机制推测当作因果结论。

由此形成的研究问题是：收益主要来自历史变短，还是来自完整计划不受中间噪声干扰？可以在同一模型和示范长度下比较完整历史 ReAct、压缩历史 ReAct、ReWOO，并逐步增加工具信息缺失和运行时分支。如果压缩历史后差距大幅缩小，上下文负担解释更强；如果预先计划在分支增加时迅速失效，就说明流程可预见性是关键前提。这个方案仅用于区分假设，本章没有开展新实验。

## 自测与答案

**问题一：第二步依赖第一步的未知结果，就一定无法预先规划吗？** 不一定。只要第二步的处理方式已知，就可以引用变量，执行时再填入结果。若第二步究竟做什么也由结果决定，才需要更复杂的分支或反馈。

**问题二：为什么 40.8→42.4 不是提高四个百分点？** 差值是 1.6 个百分点；1.6÷40.8≈3.92%，是相对提高约 4%。二者分母不同。

**问题三：Planner 与 Solver 各调用一次，为什么仍可能有四次模型调用？** 因为 Worker 里的工具也可以是模型。原图的证据提取步骤就调用了两个 LLM 工具。
