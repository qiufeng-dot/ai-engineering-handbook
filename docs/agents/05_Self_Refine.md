## 研究起点：会生成答案，是否也会识别答案的问题

写出一段通顺的话，与同时满足事实、风格、篇幅、具体要求，是不同难度的任务。以往可以训练专门的修改模型，或让人提供评价，再用评价训练模型；这些路径需要额外样本、标注或参数训练。Self-Refine 的问题更窄：**固定一个已经训练好的语言模型，让它轮流生成、评价和修改，能否改善最终输出？** 这里的改善发生在使用模型时，模型参数没有更新。

这不是“模型既然知道怎么改，为何不一次写对”的逻辑矛盾。生成时需要同时选择许多内容，评价时已有一个具体对象可供检查，任务分解可能降低困难。但这种解释只是机制动机：如果模型不知道事实真伪，或者看不出推理错误，换一个“审稿人”身份并不会产生新证据。因此，论文的核心假设是：至少在部分任务中，同一模型的评价能力足以提供有用的修改方向。判断它是否成立，要看不同任务的结果，而不能只看成功案例。[§1–2，PDF 第 1–4 页](https://arxiv.org/pdf/2303.17651v2#page=1)

## 先把原算法完整走一遍

设输入要求为文本 x，固定模型为 M，三种任务提示为 p_gen、p_fb、p_refine。符号 ∥ 表示拼接文本，y_t 是第 t 轮答案，fb_t 是该轮反馈。论文式（1）—（3）分别表达：

```text
y₀ = M(p_gen ∥ x)
fb_t = M(p_fb ∥ x ∥ y_t)
y_(t+1) = M(p_refine ∥ x ∥ y_t ∥ fb_t)
```

第一个调用产生候选答案。第二个调用必须同时看到原要求和当前答案：只有看到二者，才能判断答案遗漏了什么。第三个调用接收问题位置和修改方向。这里的反馈也是模型生成的文本，并非验证过的标签。提示中包含少量示例，因此“不进行新训练”不等于“没有任何人工先验”。

原文图 2 的代码例子是计算 1 到 N 的和。初稿循环累加，反馈明确指出循环较慢并建议等差数列求和公式，新稿使用 N(N+1)/2。以 N=4 为例，循环得到 1+2+3+4=10；把正序与逆序相加，四对数都等于 5，故两倍总和是 4×5，得到 10。这个中间推导是本讲义补出的解释，说明反馈提供的是一种算法替换，而非一般的“写得更好”。它适用于非负整数输入这一教学设定；不能忽略输入域、负数行为和语言中的整数溢出，再断言两个实现对一切输入等价。[图 2、算法 1，PDF 第 3 页](https://arxiv.org/pdf/2303.17651v2#page=3)

实际迭代还保留过去的版本和反馈，论文式（4）把第三个调用展开为：

```text
y_(t+1) = M(p_refine ∥ x ∥ y₀ ∥ fb₀ ∥ … ∥ y_t ∥ fb_t)
```

这样，下一轮能够知道已经尝试过什么，但上下文也会增长。算法依据反馈中的停止信号或轮数上限退出，正文通用设置写最多四轮，具体任务附录另有轮数安排。模型宣布“没有问题”只是停止规则，不能充当外部正确性证明。正文算法返回最后版本；附录 H 在缩写生成任务讨论按模型分数选最好版本，却将其归给算法中并未明确写出的步骤。复现时必须核实具体任务实现，不能把这些表述合并成一个无歧义算法。[§2–3.1，第 4 页；附录 H，第 22 页](https://arxiv.org/pdf/2303.17651v2#page=22)

<a id="section-3"></a>
## 七类任务必须用不同尺子阅读

论文涵盖情感反转、对话回答、代码优化、代码可读性、数学推理、缩写生成和带关键词约束的生成。附录 A 的样本规模分别为 1000、372、1000、300、1319、250、200。数学任务考查答对比例；代码优化考查程序优化成功比例；对话等任务采用模型偏好评价，并对部分样本做人类盲评；可读性另用变量命名质量等标准。它们不能合成一个统一的“正确率”。[§3.2、附录 A/C/D](https://arxiv.org/pdf/2303.17651v2#page=14)

沿用该版论文命名，GPT-3.5 指 text-davinci-003，ChatGPT 指 gpt-3.5-turbo，两者是不同实验配置；不要把下文的两组结果当成同一个模型的重复测量。[基础模型设置，PDF 第 4 页](https://arxiv.org/pdf/2303.17651v2#page=4)

表 1 中以下同一模型内的比较最有解释力：

| GPT-4 的任务 | 初始结果 → 修改后 | 应当怎样理解 |
|---|---|---|
| 代码优化 | 27.3% → 36.0% | 增加 8.7 个百分点，约为原比例的 31.9% 相对增长；不是运行速度提高 8.7%。 |
| 数学推理 | 92.9% → 93.1% | 只增加 0.2 个百分点，不能概括成数学能力大幅改善。 |
| 关键词约束生成 | 15.0 → 45.0 | 衡量关键词覆盖这一任务指标；覆盖增加不自动证明语言质量或事实性。 |
| 对话回答偏好 | 25.4% → 74.6% | 是比较输出时的偏好比例，不是答案事实正确率。 |

同一模型、相同任务提示的对照，减少了模型能力不同带来的解释。但 Self-Refine 使用更多调用，因此表 1 主要证明“迭代流程相对一次生成的收益”，尚不能单凭它证明收益全部来自反馈内容。论文另比较多样本与反馈消融，就是为了进一步拆开这个问题。[表 1，第 5 页；附录 F/H，第 18–22 页](https://arxiv.org/pdf/2303.17651v2#page=5)

## 哪些结果支持机制，哪些结果约束了它

表 2 保留迭代过程，改变反馈方式。ChatGPT 代码优化的具体反馈、泛泛反馈、无反馈结果分别为 27.5、26.0、24.8；情感反转分别为 43.2、31.2、0。与只比较初稿和终稿相比，这个对照更直接支持“指出具体问题有额外价值”。不过三种提示输入长度和生成内容并不完全相同，不应把它当成剥离了所有预算影响的因果证明。[表 2，第 6 页](https://arxiv.org/pdf/2303.17651v2#page=6)

图 4 给的是跨模型平均迭代趋势：代码优化从 22.0 到 27.0、27.9、28.8，后几次改进变小。平均趋势不保证每一个样本单调变好；附录 H 的缩写例子总分先从 11 到 17，再降到 12，随后回到 17。多目标任务可能改善读音，却破坏与原题的关联。

数学结果更能揭示瓶颈。作者观察到 ChatGPT 在大量样本中反馈“看起来都对”，因而无法启动有效纠错。附录表 9 引入一个外部正确性信号，只在答案错误时触发修改：GPT-3.5 从 64.06% 到 68.9%，GPT-4 从 92.9% 到 93.8%。这里新增了正确性信息，不能继续把收益全部称为“纯自我反馈”。正文关于提升幅度的概括也不能替代逐模型表格。[第 5–6、22 页](https://arxiv.org/pdf/2303.17651v2#page=22)

评价本身也要读。按附录 C 的总览，人类 A/B 盲评由作者进行，每个相关数据集评估 150 个样本；对话任务中偏好修改稿、初稿、无区别分别为 47.58%、19.66%、32.76%。这支持相对偏好，而非所有回答都已达到发布标准。附录 J 提供 Wilson 区间，但表注称 95%，紧接段落又写 99%，存在报告不一致；本讲义不替作者选择其中一个，更不自行宣称所有改善显著。数学的微小变化也没有被该表标为显著。[附录 C、J，第 16、28 页](https://arxiv.org/pdf/2303.17651v2#page=28)

**对话任务的复现协议还有一项实质歧义。** 前面的 372 条与 150 条分别来自附录 A 和 C；任务附录 M 却写自动评价 342 条、人评 100 条，自动裁判为 text-davinci-003，最多三轮，并在排除初稿后按反馈总分选最好版本。它与总览的样本、模型评价及选择口径不能直接合并。因此本章把主表和总览结果按各自位置转述，不声称已经还原一套唯一一致的对话实验配方。要复现需再核实代码、数据划分和具体运行记录；这是原文可复核性的限制，也说明停止、候选选择与评价者都是方法的一部分。[附录 M.2，PDF 第 32–33 页](https://arxiv.org/pdf/2303.17651v2#page=32)

<a id="section-5"></a>
## 从论文得到的设计判断与研究问题

最有根据的结论是：在这些任务和当时模型上，把可检查的要求变成具体反馈，常能提高质量；能否识别错误，决定了这种流程的上限。反馈与生成共享模型，也会共享盲点。模型把原来正确的答案改错，是应该单独统计的现象，而不能被平均提升掩盖。

一个有价值的后续问题是：同样的总 token 预算下，具体自评、独立重采样、外部规则反馈，各自帮助了哪些错误？可固定题集与最终选择规则，比较“错误变正确”“正确变错误”和总成本。若自评只在显式约束任务占优，数学上依赖外部信号，便支持“错误可识别性”这一解释。若等预算重采样已获得同样收益，则需要收窄对反馈机制的归因。此处是研究提议，本次没有调用模型验证。

**自测**：为什么“模型多改三轮”不能直接视为质量保障？因为轮数只增加机会和成本；反馈可能错误、目标可能冲突，停止与选择规则也可能把错误版本留下。要回答是否有效，必须检查任务指标及独立的判错依据。
