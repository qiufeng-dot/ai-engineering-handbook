## 为什么有反思仍需要搜索

ReAct 能边行动边使用观察，但一次生成通常沿着一条路线走；Reflexion 能在失败后给下一次尝试留下经验，仍不一定保留每个中间状态的多个候选。一个较早的错误选择可能值得回退，却没有显式的数据结构记录替代路线。LATS 的问题是：能否让模型生成候选，再用环境反馈和搜索算法决定下一笔计算花在哪里？

它连接了三类工作：生成推理步骤的语言模型、与环境交互的智能体，以及逐步分配探索预算的树搜索。与只让模型想象环境变化的方案相比，LATS 把实际返回的观察写入节点；与简单重试相比，它保留分叉结构。论文表 1 把“规划”专指使用搜索算法，因此其中给 ReAct 的规划列打叉，并不表示 ReAct 连自然语言计划都不会生成。[§2–4，PDF 第 2–5 页](https://arxiv.org/pdf/2310.04406v3#page=3)

<a id="section-2"></a>
## 原方法中的节点、价值与六个操作

节点 s 包含原问题 x、到达这里的动作 a₁…a_i 和观察 o₁…o_i；边是一个新动作。思考文本也可作为动作空间的一部分，但外部动作才真正调用环境。根节点表示还没有行动，叶节点是当前探索边界，不一定已解决问题。

图 2 的一次搜索先**选择**值得继续的节点，再让模型**扩展**多个动作，把环境返回结果接到子节点上。随后**评价**每个子节点，选较有希望的路线继续向前，称为**模拟**。这里的模拟仍可以调用真实的基准环境，不能理解为模型凭空预测所有观察。到达终止状态后，结果向经过的节点**回传**；若失败，再生成**反思**供后续选择和评价使用。成功或用尽预算时停止。[图 2，PDF 第 5 页](https://arxiv.org/pdf/2310.04406v3#page=5)

原文式（2）先组合两类线索：

```text
V(s) = λ·LM(s) + (1−λ)·SC(s)
```

LM(s) 是模型读过状态和观察后的评分；SC(s) 是相同状态下候选被重复生成所提供的一致性线索；λ 控制权重。重复被想到的动作不一定正确，因此 SC 是启发式信号，不是客观正确率。附录给出 HotpotQA、24 点任务 λ=0.5，编程与 WebShop 为 0.8。不同来源的分数还需在可比较尺度上使用，不能直接把“评分 8 分”和“频率 0.2”相加。

<a id="section-3"></a>
## UCT 公式怎样决定下一步去哪里

只选历史最高分，可能一直钻进看似不错的局部路线；平均分不高但很少试过的分支，也可能藏着答案。论文式（1）使用树搜索中的 UCT 选择式：

```text
UCT(s) = V(s) + w·√[ln N(p) / N(s)]
```

N(s) 是子节点访问次数，N(p) 是父节点访问次数，w 是探索权重。第一项利用已有质量估计；第二项补偿探索不足。固定父节点时，N(s) 越大，补偿越小；随着父节点不断被访问，一个长期忽略的子节点又会获得被尝试的机会。计数必须按实现初始化，不能让 N(s)=0 时直接除零；附录伪代码将计数初始化为一。[§3.2，第 4 页；附录 A，第 14–15 页](https://arxiv.org/pdf/2310.04406v3#page=4)

用一个讲义算例验证：父节点被访问 16 次，A 的 V=0.8、N=8，B 的 V=0.5、N=2，令 w=1。A 的总分约为 0.8+√(2.773/8)=1.389；B 约为 0.5+√(2.773/2)=1.678，所以这一次会选择 B。它不意味着 B 已经比 A 好，只意味着再调查 B 更值得。若 w=0，则退化为只看当前价值。

得到新回报 r 后，原文第 4 页以运行平均更新节点值。把新访问次数写成 N，旧均值写为 V_old，则：

```text
V_new = [(N−1)V_old + r] / N = V_old + (r−V_old)/N
```

第二个等号是代数重写，说明新结果相对旧估计的差被 1/N 加权。这里的“回传”更新的是树中的统计量，**不是反向传播训练神经网络**。第 5 页另一个表述混用了父子索引，本讲义按第 4 页和附录算法的同节点计数解释，不把有歧义的索引当成可执行规格。由于语言模型评价会受反思上下文影响，也不能直接搬来理想化搜索理论，声称本系统保证找到全局最优答案。

## 实验成功率必须和搜索协议一起读

HotpotQA 使用 100 个问题，GPT-3.5，常用每次扩展 n=5、最多 k=50 条轨迹。表 3 中 ReAct 为 0.32，重复采样版本为 0.38，Reflexion 为 0.51，LATS(ReAct) 为 0.63；先内部推理、失败后转检索的混合版本达到 0.71。**该实验允许环境在提交答案后提供正确性反馈**，所以它主要考查在可靠反馈下利用搜索的能力。没有这种反馈的真实问答，不能直接引用 71% 作为预期水平。[§5.1、表 2–3，第 6 页](https://arxiv.org/pdf/2310.04406v3#page=6)

编程实验中，每个动作直接是一份完整程序，因此跳过向更深处模拟。候选程序在内部测试上的通过比例充当搜索回报。正文统一写生成四个测试，但附录 D.2 明确 HumanEval 的 GPT-3.5 用六个、GPT-4 用四个，本章保留这一更细的配置差别。扩展 n=5、轨迹 k=8，最后选一个候选，才在真实测试上评估 pass@1。表 4 的 GPT-4 HumanEval 为 92.7%，Reflexion 为 91.0%。这不是一次生成的胜率，也不是二者同样总 token 预算的保证。脚注明确：部分基线只用 161 道题，LATS 用全体 164 道题；不能把小差值当成已严格隔离的数据同条件优势。[§5.2、表 4–5，第 7 页](https://arxiv.org/pdf/2310.04406v3#page=7)；[附录 D.2，第 16 页](https://arxiv.org/pdf/2310.04406v3#page=16)

WebShop 使用 50 条指令，n=5、k=30。平均得分衡量满足购物要求的程度，成功率要求全部条件满足，二者必须分开：

| 方法 | 平均得分 | 全条件成功率 |
|---|---:|---:|
| ReAct | 53.8 | 28.0% |
| ReAct 多次采样 | 59.1 | 32.0% |
| Reflexion | 64.2 | 35.0% |
| LATS | 75.9 | 38.0% |
| 表中引用的微调方法 | 67.5 | 45.0% |

LATS 的平均分比 ReAct 高 22.1 分，但成功率只高 10 个百分点；它也没有在成功率上超过表中所有微调结果。平均满足更多属性，与更常全部成功是不同目标。基准中的购买动作是环境任务，不能据此推断实际支付系统支持任意回退。[表 6，PDF 第 8 页](https://arxiv.org/pdf/2310.04406v3#page=8)

24 点任务补充检验纯推理：表 7 的 CoT、Reflexion、ToT、RAP、LATS 成功率依次为 0.08、0.12、0.20、0.40、0.44，n=5、k=30。它支持搜索也能用于没有网页工具的推理任务，但这仍是有可计算目标的受限问题。

<a id="section-5"></a>
## 消融、成本与可回退这一前提

HotpotQA 表 8 中，完整 LATS 为 0.63，去掉反思降到 0.58，改为深度优先搜索降到 0.42，去掉模型启发式评价降到 0.37。这表明评价与搜索组织承担了重要作用。不过更换搜索同时影响访问顺序、剪枝和回传，不能把 21 个百分点完全归给某一行公式。

表 9 的 token 成本在“搜索成功”的样本上统计：LATS 173,290，RAP 176,500，ToT 210,215。只统计成功案例会受成功题目构成影响，不能代替所有请求的平均成本；也不能用相同的 O(kn) 阶数推断真实延迟相同。附录对 HotpotQA 最大深度还有 7 与 6 的不同描述，若复现需要检查配置。本次没有替作者消除这些协议不确定性。[第 9、14–15 页](https://arxiv.org/pdf/2310.04406v3#page=9)

方法最强的前提是能够回到旧状态。在文本推理或可重置模拟环境中，复制上下文和恢复环境通常可行；实际发送消息、付款、修改账户后，仅还原提示词不会撤销外部世界。环境快照、动作副作用和失败恢复因此属于采用树搜索前的必要条件，而不是附带工程优化。

一个有针对性的后续研究是：固定所有方法的总 token 和环境调用预算，分层比较高可靠反馈与带误判反馈，统计最终质量、总成本及错误回传造成的搜索偏移。若 LATS 只在准确奖励下领先，主要瓶颈就是评价；若噪声增加仍能借多分支恢复，则支持搜索的容错价值。此处仅提出方案。

**自测**：节点分数很高，是否可以当作任务完成证据？不可以。启发式分数用于分配探索，最终完成仍取决于任务的独立验证条件。
