<a id="section-1"></a>
## 从“一步步想”到“具体应该分成哪些步骤”

“一步步思考”能提醒模型展开过程，却没有说明哪种过程适合当前任务。判断几何路径、追踪物体颜色、分析人物知道什么，需要不同的中间表示。Plan-and-Solve 让模型先计划，但这个计划可能仍很笼统。Self-Discover 的研究问题是：能否从已有的通用思考方法中选择、改写并组合出适合某类任务的结构，然后反复用于该类题目？

这里的“模块”是自然语言描述，例如分解问题、质疑假设、逐步计算，并非可执行插件，也不是具有独立参数的神经网络层。“发现结构”仍由语言模型生成文字完成，没有搜索算法证明结构最优。本文的贡献在于一种组织提示与中间推理的流程，以及对效果、调用次数和结构迁移的实验。[§1–2，第 1–3 页](https://arxiv.org/pdf/2402.03620v1#page=3)

<a id="section-2"></a>
## 两个层次：为任务准备结构，为实例填写结构

第一阶段看一类任务的无答案示例，选出有帮助的思考方法，改写成任务专用步骤，再排成键值结构。第二阶段把结构与一道具体题一起提供给模型，让它填写每个步骤的内容，最后作答。通常第一阶段只做一次，第二阶段反复做；但 MATH 实验为了适应题目复杂性，采用逐实例构造结构，不能套用“每类题只准备一次”的全部效率结论。[§2、§3.1，第 3–4 页](https://arxiv.org/pdf/2402.03620v1#page=4)

令 D 为原始模块描述集合，t_i 为无标签示例，M 为固定模型。用 S、A、I 分别代表选择、适配、落实，流程可重构为：

```text
D_S = M(p_S ∥ D ∥ t_i)
D_A = M(p_A ∥ D_S ∥ t_i)
D_I = M(p_I ∥ S_human ∥ D_A ∥ t_i)
Answer(t) = M(执行提示 ∥ D_I ∥ t)
```

所有 D_* 都是文本结构。D_S 说明选哪些方法，D_A 说明这些方法在当前任务中怎么做，D_I 给出执行次序与需要填写的中间结果。S_human 是另一任务上的人工结构示例，因此不使用当前任务答案，不等于完全没有人类设计。

这组公式是按正文与附录提示统一后的讲义记法：原版第 3 页式（3）文字介绍 p_I，公式却写 p_A；式（4）文字介绍已落实的 D_I，公式却写 D_S。图 2 与附录 A 支持“执行最终结构”这一解释，但本次没有验证仓库以哪套变量实现。把差异说明白，比悄悄抄出一组看似严谨的公式更有助于复现。[式（1）—（4），第 3 页；附录 A，第 12 页](https://arxiv.org/pdf/2402.03620v1#page=12)

<a id="section-3"></a>
## 跟着原论文的几何题看中间表示为何重要

图 7 给出一串 SVG 绘图指令，要求判断形状。字母 M 表示移动起点而不画线，L 表示向下一个坐标画直线。原题依次连接七个不同顶点，最后回到起点。判断的关键不是它是否规则，而是线段怎样连接、是否闭合、有多少边。

原例中的 CoT 与 Plan-and-Solve 把路径判成不闭合，或错误地数成四条线，最后选了风筝形。Self-Discover 生成的结构要求先分解路径命令、逐条记录起终点，再检查连续与闭合，最后数顶点，因此选出七边形。沿原题手工核对也可看到：第一条 M 不算一条边；接着的七条 L 形成七个边；末端坐标等于第一起点。这个例子解释了结构如何迫使模型保留关键中间事实，而不是把“多想一会儿”当成原因。[图 7，PDF 第 7 页](https://arxiv.org/pdf/2402.03620v1#page=7)

不过一张成功示例并不证明结构普遍更好。JSON 外形也不提供正确性保障：字段可以齐全，填入的坐标或计数仍然错误。算法式结构与算法的正确执行是两个问题，后面的数学错误分析正好把它们分开。

<a id="section-4"></a>
## 主结果要按任务拆开，不能只引用最大提升

论文比较 23 类 BBH 任务、关于社会情境下行动选择的 T4D，以及 MATH 的 200 道抽样题。MATH 的答案提取还经过人工检查。表 1 是任务组级汇总：

| 模型与任务 | CoT → Self-Discover | 读法 |
|---|---|---|
| GPT-4 / BBH | 75% → 81% | 汇总提高 6 个百分点，内部并非每类任务都提高。 |
| GPT-4 / T4D | 52% → 85% | 按表格计算为 33 个百分点；相对 PS 的 53% 是 32 个百分点。 |
| GPT-4 / MATH | 71% → 73% | 200 道抽样题上的温和改善，不能写成提高 32%。 |
| PaLM 2-L / BBH | 60% → 67% | 提高 7 个百分点。 |
| PaLM 2-L / T4D | 40% → 69% | 提高 29 个百分点。 |
| PaLM 2-L / MATH | 42% → 50.5% | 提高 8.5 个百分点；本文 MATH 使用更强指令调整的 PaLM 2-L 配置。 |

“最高提升约 32%”不能替代这些比较。具体差值取决于比较对象，而且应以百分点表达。附录表 3 的 GPT-4 多步算术从 92% 降到 70%，物体置换跟踪从 80% 降到 68%；它表明任务专用结构也可能干扰原本有效的推理。图 4 的“世界知识类平均获益较多”是类别平均，不能覆盖这些反例。[表 1，第 5 页；附录 C，第 14 页](https://arxiv.org/pdf/2402.03620v1#page=14)

数学错误分析更具体：200 题中 175 个结构被人工判为正确，标准是专家沿结构可以解出题；99 个最终错误中，25 个来自结构问题，其余 74 个来自中间执行。于是 74/99≈74.7%，分母是错误答案数，不是全部 200 题。结构正确率 87.5% 也不是模型最终解题准确率。[附录 D，第 12、14 页](https://arxiv.org/pdf/2402.03620v1#page=14)

<a id="section-5"></a>
## 调用次数、消融和跨模型迁移

图 5 在电影推荐与几何两类任务上，比较单次解题、多次采样投票与模块组合。Self-Discover 每类任务先花三次调用，再对每个实例调用一次。对 K 道同类题，讲义推导的平均调用数为 (K+3)/K=1+3/K；K=100 时为 1.03，K=1 时却是 4。相比每题十次或约四十次调用，它在大批同类题上能分摊准备成本。**调用数不同于 token 数、延迟或价格**，因为结构使输入输出变长；原文图注也承认这一点。附录列 39 个模块，正文某些成本表述按 40 计，复現时需要统一实际模块清单。[§4.3、图 5，第 6 页；附录 A，第 13 页](https://arxiv.org/pdf/2402.03620v1#page=6)

图 8 比较只选择、选择并适配、完成三个阶段。在 T4D 中结果逐步上升，而几何任务从只选择的 50 到加适配的 45，最后加入结构落实到 61。故“最终组合较好”有证据，“每个新增阶段都在每类任务单调提高”不符合图中所有数值。各阶段也改变了提示长度和具体内容，进一步隔离结构形式与信息量，需要更严格的等内容比较。[图 8，第 7 页](https://arxiv.org/pdf/2402.03620v1#page=7)

迁移实验把 PaLM 2-L 发现的结构给 GPT-4，四类任务中三类超过从同一来源模型优化得到的 OPRO 提示；另把 GPT-4 结构用于 Llama2-70B 的消歧问答，42% 到 52%。这支持某些结构可以迁移，但覆盖范围还不足以证明“对所有模型通用”。给 ChatGPT 的几何迁移还用了三个结构推理示例，不能写成与全部零样本设置完全相同。[§5.2，第 7–8 页](https://arxiv.org/pdf/2402.03620v1#page=8)

<a id="section-6"></a>
## 怎样从这里继续研究

最稳妥的设计启发是：当许多题确实共享操作结构时，把“该检查哪些中间事实”显式化，可能比一个通用口号更有帮助；当题目变化很大、结构错误或计算执行不可靠时，它就可能失效。结构是对问题的假设，需要检验，不是漂亮的表单。

可进一步固定模型与 token 预算，比较同一内容的连续文字计划、JSON 结构、随机排列结构，并将样本分成同任务与分布变化两组。如果只有合理顺序而非 JSON 外形有效，收益主要来自内容组织；如果遇到新题型时共享结构明显退步，便应检测何时需要重新构造，而不是永久缓存一份结构。这个实验能区分“结构性帮助”“额外提示信息”和“表面格式效应”，本次未执行。

**自测**：175 个结构正确，为什么只有 101 个答案正确？因为结构告诉模型怎么走，不能替它保证每一步算对。这两项都以同一组 200 道题为分母，区别是判断对象：一项检查推理结构，另一项检查最终答案；不能把结构正确率当作答案正确率。
