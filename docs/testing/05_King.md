## 一、从“选几个数字运行”到“先不决定数字”

测试一个求和函数时，输入 1、3、5 得到 9，只直接检查了这一组输入。我们可以再测负数、零或很大的数，但还会剩下更多输入。另一种办法是写出完整规格，对程序作形式证明；它可能给出更强保障，却需要严格规格、中间断言及机器算术处理，代价很高。

King 的问题是在两者之间寻找一种实用途径：能否沿着程序计算，但暂时把输入保留为未知量，使一次计算描述一类具体运行？如果 x 尚未确定，执行 y=2x+1，仍然能得到表达式 2x+1。程序没有停止运行，只是把依赖输入的计算保存在公式里。这种分析方式叫符号执行。[§1–2，PDF 第 1–2 页](https://lim.univ-reunion.fr/staff/fred/Enseignement/Verif-M2/Articles/Autres/Symbolic-execution-and-Program-Testing-King-1976.pdf#page=1)

这篇论文的贡献不能压成“用字母代替数字”。更关键的问题是：程序遇到分支时怎样处理；公式结果为何能代表正常运行；循环怎样使方法重新遇到有限测试的边界；用户又如何把正确性要求接进来。作者与 SELECT、Clarke、Deutsch 等同时期工作存在联系，本文没有把思想来源归结为一个孤立发明。

先明确理论范围。第 2 节的理想语言只有任意大小的有符号整数，以加、减、乘构造多项式，分支条件可写成 R≥0，不考虑寄存器溢出。作者一开始就承认：执行树可能无限，判断所有条件所需的自动推理能力也不能一般获得。下面先在这个理想模型中理解机制，随后再看实际系统损失了什么。

<a id="section-2"></a>
## 二、跟着原文 SUM，看执行状态如何逐步变化

原文首先使用一个很小、没有分支的程序。它看似绕了一步，但正好揭示表达式如何沿赋值传播：

```text
SUM(A,B,C):
    X = A+B
    Y = B+C
    Z = X+Y−B
    return Z
```


给 A、B、C 分别输入 α₁、α₂、α₃。第一行后，X=α₁+α₂；第二行后，Y=α₂+α₃；第三行先将 X、Y、B 换成当前表达式，再化简：

```text
Z = (α₁+α₂)+(α₂+α₃)−α₂
　= α₁+α₂+α₃
```

中间出现两次 α₂，最后减掉一次，才得到三个输入的和。代入原文的 1、3、5，输出为 9。这里的一条执行没有按输入大小分支，所以同一个表达式描述所有三整数输入。[图 1–3，PDF 第 3–4 页](https://lim.univ-reunion.fr/staff/fred/Enseignement/Verif-M2/Articles/Autres/Symbolic-execution-and-Program-Testing-King-1976.pdf#page=3)

为了继续处理分支，状态中除了变量值和当前语句位置，还须有一份“走到这里必须满足什么”的记录，叫路径条件，论文记为 pc。它以最初输入符号表达，而不是以不断被改写的程序变量表达。这样，后续修改 X 不会悄悄改变前面条件的含义。分析开始时 pc=true；每作出一次尚未确定的分支选择，就增加对应限制。

<a id="section-3"></a>
## 三、分支不是盲目复制：先问当前条件是否已经决定方向

遇到 IF 时，先把其中的程序变量替换为当前表达式，得到条件 q。再检查两个逻辑命题：

```text
pc ⇒ q
pc ⇒ ¬q
```

若第一行成立，所有符合当前路径的输入都会走真分支；若第二行成立，则都会走假分支。只要 pc 本身可满足，两行不可能同时成立。此时不需要增加新的假设，也不需要产生第二条状态。例如已知 x≥5，再遇到 x≥0，方向已定。

真正需要分叉的是两边都有可能的情况。系统复制分支前的变量状态，一份走真方向并令 pc←pc∧q，另一份走假方向并令 pc←pc∧¬q。合取号表示“同时成立”，它保存全部路径历史。若只保留最近条件，最终找到的输入可能根本无法通过前面的判断。[§2，PDF 第 2–3 页](https://lim.univ-reunion.fr/staff/fred/Enseignement/Verif-M2/Articles/Autres/Symbolic-execution-and-Program-Testing-King-1976.pdf#page=3)

作一个补充演算：先执行 y=2x+1，再判断 y>10，真分支中又判断 x<8。在整数语义下，第一个真分支要求 x≥5，第二个真分支要求 x≤7，所以这条路线对应 5≤x≤7。选择 x=5 可以重现；若只记最后的 x<8 而选 x=0，第一关便过不了。若第二判断改成 x<3，两条件矛盾，没有输入能走通该路线。

这个例子同时说明“未确定”与“不可行”的区别。数学上证明矛盾，才支持排除路径；一个实际求解工具超时或不支持某种表达式，只说明尚无结论。作者在第 9 节正是用这个差别提醒读者：理想语义中的可行性保障，未必由现实实现完全兑现。

<a id="section-4"></a>
## 四、POWER：一条路径表示许多输入，却仍可能有无限多路径

论文第二个程序计算幂：先令 Z=1、J=1；只要 Y≥J，就令 Z=Z×X、J=J+1，再回到判断；退出时返回 Z。给 X、Y 输入 α₁、α₂，跟着图 5 逐次推进：

| 当前阶段 | 路径条件 | 返回结果或下一步 |
|---|---|---|
| 第一次判断直接退出 | α₂<1 | 返回 1 |
| 做一次乘法后退出 | α₂≥1 且 α₂<2，即 α₂=1 | 返回 α₁ |
| 做两次乘法后退出 | α₂≥2 且 α₂<3，即 α₂=2 | 返回 α₁² |
| 做 n 次乘法后退出 | α₂≥n 且 α₂<n+1，即 α₂=n | 返回 α₁ⁿ |

从不等式化为等式，使用了“α₂ 是整数”这一前提，若把输入换成实数就不能原样推导。一般行是讲义按原轨迹补出的归纳概括，不代表执行器已经自动完成归纳证明。[图 4–6，PDF 第 5–7 页](https://lim.univ-reunion.fr/staff/fred/Enseignement/Verif-M2/Articles/Autres/Symbolic-execution-and-Program-Testing-King-1976.pdf#page=6)

每个正整数指数都有一个退出分支，树还有继续增加指数的无限骨架。因此，虽然某个固定指数分支一次就代表所有底数，依次穷尽全部指数仍做不到。路径条件压缩的是同一路线上的输入，并没有自动把路线数量变成有限。

还要注意第一行：Y<1 时都返回 1，包括负整数。程序会这么做是一项分析结果，它是否正确却取决于规格。若函数只允许非负指数，应通过输入前提限制；若要求负指数产生分数，这个实现与当前整数语言都不够。执行代码与知道任务意图是两个问题。

<a id="section-5"></a>
## 五、TWOLOOPS 与交换性：为什么公式真的对应程序执行

接着，论文给出两个先后从 1 循环到同一 N 的循环。第一个循环的分叉已经让 pc 确定 N 所属的类别，第二个同样的循环不必再次制造所有可能分叉。图 8 中，第一循环每个退出点接向第二循环的确定链。这说明分叉属于某一次执行时的知识状态，而不是某条 IF 语句永久具有“必须一分为二”的属性。[图 7–8，PDF 第 8 页](https://lim.univ-reunion.fr/staff/fred/Enseignement/Verif-M2/Articles/Autres/Symbolic-execution-and-Program-Testing-King-1976.pdf#page=8)

在理想定义中，可以证明两个重要性质。第一，每个完成执行的终叶有某个具体输入能到达，因为只在约束可满足时加入新分支。第二，两个不同终叶的路径条件互不相容，因为它们最初分开的地方，一个加入 q，另一个加入 ¬q；后面继续增加条件不会消除这一冲突。

更根本的是第 5 节讨论的交换性：先把符号替换成具体输入 K 再执行，与先符号执行、再把 K 代入对应结果，得到同样值。图 9 把两种顺序画成一个方框。但“对应结果”不是任意终叶，而是 **pc 被 K 满足的那个终叶**。将 x=0 强行代入前面的错误路径表达式，虽然能算出 y=1，也不能证明 x=0 会到达错误位置。[§4–5、图 9，PDF 第 3–4、8 页](https://lim.univ-reunion.fr/staff/fred/Enseignement/Verif-M2/Articles/Autres/Symbolic-execution-and-Program-Testing-King-1976.pdf#page=4)

这个性质依赖两种执行采用相同算术和存储语义，也只描述有结果的执行。树中存在一些终叶，不等于所有输入都终止。如果机器会溢出，或者浮点加法不满足理想实数的变换规则，随意化简可能破坏这个方框。

## 六、SEARCH 的 11 个终叶：从有限子树逐渐放松约束

EFFIGY 将上述能力做成交互调试系统。用户可以保存状态、恢复状态，选择 go true 或 go false，也可以添加假设后重新判断。论文用一个二分搜索程序说明怎样实际测试，而不是仅画理想执行树。

SEARCH 在有序数组 A 的 L 到 U 之间寻找 X，找到时返回 FOUND=1、J=位置；未找到时返回 FOUND=0，J 指向插入间隙的左界。第一次调用固定 L=1、U=5，但 X 和五个数组元素都保留为符号。中间下标是 3，于是先问 X 是否等于 A(3)。选真即得到命中位置 3；保存后回到同一状态，选假，再按小于或大于 A(3) 搜索左右区间。[§7、图 10，PDF 第 6–8 页](https://lim.univ-reunion.fr/staff/fred/Enseignement/Verif-M2/Articles/Autres/Symbolic-execution-and-Program-Testing-King-1976.pdf#page=6)

作者完整列出 11 个终叶，可理解为五个命中位置加六个可能插入间隙。例如：

| 路径积累的关系 | FOUND | J |
|---|---:|---:|
| X=A(3) | 1 | 3 |
| X=A(1) 且 X<A(3) | 1 | 1 |
| X<A(1) 且 X<A(3) | 0 | 0 |
| X=A(2) 且 X>A(1) 且 X<A(3) | 1 | 2 |
| X>A(1) 且 X<A(2) 且 X<A(3) | 0 | 1 |

这不是五个具体数组的结果，而是程序控制流对关系作出的划分。数组有序是搜索问题的规格前提，不能误写成执行器仅靠这些路径就证明了任意数组都已排序。

随后作者把区间换成 N 到 N+4。长度仍为五，位置整体平移，依旧得到对应的 11 类；换成 N 到 N 只剩相等、较小、较大三类。最后使用 1 到 N 或 L 到 U，连长度也变成符号，执行树便可能无限。这套顺序展示了一种实际策略：先固定规模穷尽有限子树，再抽象起点，最后抽象规模，逐步检查新的行为。

系统的 TEST(200) 会自动探索语句执行次数小于 200 的路径。200 是执行步数界，不是 200 个测试，也不是已证明程序在 200 步内终止。作者明确说这些 SEARCH 步骤确实在 EFFIGY 做过，但本次阅读没有取得或重放系统会话。论文同时承认实际使用仍很有限，没有提供大规模缺陷检出率和运行成本表供我们评价。[§7、§10，PDF 第 6–7、10 页](https://lim.univ-reunion.fr/staff/fred/Enseignement/Verif-M2/Articles/Autres/Symbolic-execution-and-Program-Testing-King-1976.pdf#page=7)

## 七、从测试走向证明：ASSUME 与 PROVE 各自做什么

路径可行并不等于结果正确。第 8 节把表示正确性的断言引入执行过程，并严格区分两个动作：

```text
ASSUME(B)：pc ← pc ∧ value(B)
PROVE(B)：检查 pc ⇒ value(B)
```

value(B) 表示用当前变量的符号表达式求出 B。ASSUME 是限定分析范围，不能把“假定正确”当成证明；PROVE 才尝试判断在当前全部前提下 B 是否必然成立。普通运行时的 assert(B) 可以看作 if ¬B then error，要证明错误分支不会执行，恰好也是检查 pc⇒value(B)。[§8，PDF 第 7–9 页](https://lim.univ-reunion.fr/staff/fred/Enseignement/Verif-M2/Articles/Autres/Symbolic-execution-and-Program-Testing-King-1976.pdf#page=7)

Floyd 的证明方法还要求在循环中放入归纳断言，把无限执行切成有限条有限长度片段。每条片段开头的 ASSERT 改成 ASSUME，结尾改成 PROVE；将变量初始化为互异符号，沿指定片段执行，把分支条件加入 pc，最后证明末端断言。由交换性，对符号路径成立的蕴含也适用于相应具体执行。难点转到断言是否恰当，以及逻辑推理是否成功；系统没有凭空消除这些任务。

以 POWER 作一个明确标为讲义补充的推导。假设 Y 为非负整数，幂按重复乘法定义，空乘积为 1。循环前可建立 Z=X^(J−1)，J=1。若某轮开始该等式成立，乘一次 X、J 加一后，新 Z=X^J，恰等于 X^(新 J−1)，所以关系保持。再维持 1≤J≤Y+1；退出时 Y<J，由整数性质得到 J=Y+1，于是 Z=X^Y。这个有限的初始化、保持、退出论证，解释了归纳断言怎样跨过无限执行树。它并非论文声称 EFFIGY 自动发现了这条不变量，也没有替任意程序证明终止。

对于有限树、明确输入输出断言的程序，穷尽符号执行可以与逐路径证明重合；对于无限树，归纳信息仍不可缺。论文讨论的正确性首先是“如果执行产生结果，则结果满足要求”的部分正确性，不宜自动升级为终止也已证明。

## 八、实际系统在哪些地方偏离理想

符号下标 A(I) 可能指向多个数组单元。可以按 I 的可能值分叉，但状态会增多；也可以保留条件表达式，让“若 I=1 就取某值，否则……”继续传播，但公式会变复杂。路径增长和表达式增长在这里是两种不同的成本，无法只靠一个口号解决。[§9，PDF 第 9–10 页](https://lim.univ-reunion.fr/staff/fred/Enseignement/Verif-M2/Articles/Autres/Symbolic-execution-and-Program-Testing-King-1976.pdf#page=9)

自动推理也可能没有能力识别一个实际上不可行的分支，结果探索真实程序永远走不到的路线。因此，理想证明的“每个终叶都有具体输入”，不能不加条件地套给所有现实符号执行器。将生成输入放回普通程序重放、核对机器语义和环境，正是后续系统论文需要解决的部分。

最稳妥的结论是：符号执行能够以输入条件和输出表达式描述一类程序行为，并在给定错误条件或断言时求出反例或证明局部性质。它减少逐个猜输入的负担，但正确规格、无限路径、求解能力和机器语义都仍然决定边界。

一个可检验的后续问题是：保留前段路径条件，究竟减少了多少后段重复分叉？可以固定一个含重复条件和两个相同循环的有界程序，对照是否复用已知条件，记录真实可行路径、状态数以及求解未知数。若机制确实是信息复用，减少应集中在已由前段确定的判断；若只是删掉未知状态造成数字变小，就没有证明更准确。这里是研究设计，没有运行作者系统或新测试平台。

<a id="section-9"></a>
## 自测与答案

**问题一**：POWER 的 α₂≥1 且 α₂<2 为什么能写成 α₂=1？

**答案**：因为原模型是整数。若输入允许实数，区间中还有无限多个值，推导便不成立。

**问题二**：ASSUME(result=expected) 能证明结果正确吗？

**答案**：不能。它只是排除了不满足该关系的状态；要检查当前所有允许输入是否都满足关系，应使用相应的 PROVE。

**问题三**：SEARCH 在固定五元素范围穷尽 11 类，是否等于验证任意长度数组？

**答案**：不等于。固定长度得到有限子树；把长度变成符号可能产生无限树，需要额外归纳论证或明确的规模界。
