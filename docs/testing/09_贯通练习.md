<a id="section-1"></a>
## 一、规格先于代码：我们究竟要判断什么

设输入为金额 x、会员标志 B、优惠资格标志 C。x 以“分”为单位，只接受 0 到 100,000,000 的整数；B、C 必须为布尔值。非法输入返回错误，不产生应付金额。合法输入中，金额达到 10,000 分，而且会员或优惠资格至少满足一个，才能打折。折扣额取 x/10 向下取整，应付金额 y＝x−⌊x/10⌋；其余情况 y＝x。

用 A 表示 x≥10,000，则折扣决策是 D＝A∧(B∨C)。这一步把金额这一有序数值与是否触发折扣这一布尔判定分开，后面才知道哪些问题需要边界方法，哪些需要逻辑组合。规则中的单位、取整和非法输入处理也不能留给实现者临时猜测。

下面是为讲解而写的参考实现。它展示我们要研究的结构，不是已测试通过的产品代码。

```text
若 x 不是规定范围内的整数，或 B、C 不是布尔值：返回输入错误
A ← x ≥ 10000
若 A 且 (B 或 C)：
    y ← x − floor(x / 10)
否则：
    y ← x
返回 (是否打折, y)
```


需求已经规定了答案，但仍可能不符合真实业务。比如业务人员原本想对优惠券再判断有效期，本规格却没有这个输入。任何针对这份规格的高覆盖测试，都无法自动证明规格本身完整。这是需求评审与程序测试的边界。

<a id="section-2"></a>
## 二、黑盒选样：边界与组合不能互相代替

从金额规则出发，首先区分非法与合法输入，再把合法范围按打折阈值分开。对离散整数，阈值附近至少关注 9,999、10,000、10,001；外层合法范围还要考虑 −1、0、1，以及 99,999,999、100,000,000、100,000,001。每次比较时，B、C 应安排成能够让金额边界影响结果，例如 B＝真、C＝假。

若 B、C 都是假，10,000 上下都不打折。测试输入虽然“碰到了阈值”，输出却没有暴露金额比较符号的错误。假设实现误写为 x＞10,000，只有把恰好 10,000 与有效资格配在一起，才会出现期望 9,000、实际 10,000 的差别。边界值不是只把数字写进用例表，还要让其他条件保持有辨别力。[方法依据：ISTQB 章](./01_ISTQB.md)

三个布尔因素 A、B、C 的全组合有 8 行。下面 4 行覆盖每一对因素的所有四种取值，即 pairwise 完整：

| 用例 | A | B | C | D＝A∧(B∨C) |
|---|---:|---:|---:|---:|
| P1 | 0 | 0 | 0 | 0 |
| P2 | 0 | 1 | 1 | 0 |
| P3 | 1 | 0 | 1 | 1 |
| P4 | 1 | 1 | 0 | 1 |

你可以分别投影 AB、AC、BC，都会得到 {00,01,10,11}。这里没有约束，分母为 3×4＝12 个成对取值组合；覆盖率为 12/12。可是 111 这一完整配置没有出现。如果缺陷只在金额达标、会员、优惠资格同时存在时错误地叠加两次折扣，这组完整 pairwise 测试就会漏掉它。由此可见，覆盖所有二阶交互不等于覆盖三阶交互，更不是覆盖所有需求。[方法依据：NIST 章](./02_NIST.md)

金额也不能简单由 A 的真假代替。A＝真对应很多金额，只有 10,000 能区分 `≥` 与 `>`，10,001 又涉及取整。组合覆盖对选定因素和取值负责；因素划分丢掉的数值细节，应由边界和其他针对性测试补足。

<a id="section-3"></a>
## 三、白盒配对：每个条件是否真正改变过决策

如果只要求 D 的真假都出现，P1 与 P3 就够了，但 B 从未取真，不能证明它对输出产生过作用。MC/DC 进一步要求每个条件都能在适当配对中独立影响 D。对于这个没有重复条件的布尔表达式，可以采用下表的 unique-cause 配对：

| 用例 | A | B | C | D | 用途 |
|---|---:|---:|---:|---:|---|
| M1 | 0 | 1 | 0 | 0 | 与 M3 配对检查 A |
| M2 | 1 | 0 | 0 | 0 | 与 M3 检查 B，与 M4 检查 C |
| M3 | 1 | 1 | 0 | 1 | A、B 两个配对的另一端 |
| M4 | 1 | 0 | 1 | 1 | C 配对的另一端 |

M1→M3 只改变 A，D 随之改变；M2→M3 只改变 B；M2→M4 只改变 C。这些是对逻辑赋值的分析。若真实语言采用短路计算，某些条件并未执行，运行报告必须按实际求值与所采用的覆盖定义处理，不能把逻辑上可推知的值冒充执行观察。[方法依据：NASA 章](./03_NASA.md)

这组 MC/DC 用例没有 111，也不是完整 pairwise 集合。反过来，前面四个 pairwise 用例找不到 B 的独立影响配对：要让 B 改变 D，必须固定 A＝1、C＝0，并比较 100 与 110，前者缺失。因此，对这个具体测试集，pairwise 完整与 MC/DC 完整并不互相替代。我们是在比较已经给出的集合，没有证明任意程序上两种准则的统一包含关系。

Zhu 的理论提醒我们，即使某种准则在形式上包含另一种，也必须区分“满足了哪些义务”与“某次生成具体选中了哪些测试”。知道包含关系，不能直接给现实测试集按检错能力排名。[理论依据：Zhu 章](./04_Zhu.md)

<a id="section-4"></a>
## 四、符号执行怎样反推出输入，又在哪里停下

把金额 x 保留为符号，想走“金额达标、非会员、但有优惠资格”的打折路径，需要满足：

```text
x∈整数 ∧ 0≤x≤100000000 ∧ x≥10000 ∧ ¬B ∧ C
```

求解器可以给出 x＝10,000、B＝假、C＝真。沿这条路径，输出表达式是 x−⌊x/10⌋；代入得到 9,000。这里路径条件描述什么输入能走到分支，输出表达式描述在该路径上如何计算。若金额被误写为严格大于，路径条件相应变化，但仅仅为错误程序找到一条可行路径，还不能识别它违反了正确规格。[机制依据：King 章](./05_King.md)

一个更有针对性的验证问题是：是否存在合法输入，使实际实现的输出不等于规格规定的输出？把两个表达式不相等作为待求条件，x＝10,000 且有资格就可能成为反例。这要求有独立规格，而且金额运算、范围、溢出和取整语义建模正确。无解结论也只能覆盖建模的域与已处理的路径，不能自动推广到所有外部环境。

KLEE 的贡献在于把这类方法推进到真实系统程序：共享状态、优化约束查询、选择搜索路径，并为文件等外部环境建模。读完它应认识到，能在这个小例子上手算并不表示可以不付成本地覆盖一个大型系统；循环、复杂内存和外部行为会把状态空间迅速放大。[系统依据：KLEE 章](./06_KLEE.md)

<a id="section-5"></a>
## 五、判断答案：有性质不等于有完整规格

本例可以从明确规则直接算预期。例如 x＝10,001 且 B＝真时，折扣额是 1,000，应付 9,001。与正确期望比较，比只看“没有抛异常”强得多。如果测试使用同一段实现代码再算一次期望，相同错误可能复制过去，形式上有断言却没有独立判断依据。

有些测试不需要为每个输入写死答案，而是比较相关运行之间应该保持的关系。固定合法 x 和 C，把 B 从假变真，应付金额不应增加；当 B 已经为真时，改变 C 不应再改变本规格下的金额。这些是由本例规格推导的关系，适合检测某些错误，不能覆盖所有折扣错误。例如实现始终返回零，也满足“不增加”这一弱性质。

另一个看似合理的性质却是错的：“购物金额越高，应付金额绝不会下降。”当会员从 x＝9,999 增到 10,000 时，y 从 9,999 降到 9,000。错误的测试性质会把正确实现判失败。Oracle 综述所强调的正是这一点：判定器也有前提，关系应从需求或可验证的性质中来，不能只凭常识猜测。[判定依据：Oracle 章](./08_Oracle.md)

<a id="section-6"></a>
## 六、如何阅读一份测试报告，而不是只盯覆盖率

设一份报告称“所有分支都跑过，测试通过”。你现在应追问：是否包括非法输入？边界值是否有资格条件配合？有没有 111 的叠加行为？断言是否检查了取整与精确金额？覆盖目标有没有不可达项？这些问题分别对应需求、选样、结构、判定和分母。

在 ICSE 2014 的五个项目样本中，忽略测试集大小得到的相关性，比同规模组内通常更强。这提醒我们防止把数量带来的共同增长解释成覆盖率本身的质量作用。在这个练习里也一样：为了提高覆盖新增十个只检查“不崩溃”的输入，不一定比增强一个关键断言更有价值。但哪种投资更好仍要靠项目证据，不能把研究标题当作放弃覆盖测量的理由。[实证依据：覆盖与效果章](./07_Coverage_Effectiveness.md)

<a id="section-7"></a>
## 七、练习与参考解答

**题目一：把 P1–P4 的金额分别设置为 0、9,999、10,001、20,000，是否测到了 `≥` 被写为 `>` 的错误？**

答案：没有。A 的真假与所有成对组合都覆盖了，但没有满足资格且 x 恰好为 10,000 的用例。缺口来自数值边界，不来自这三项布尔因素的 pairwise 覆盖。

**题目二：给 MC/DC 集合补一个 111，就可以称“完整逻辑测试”吗？**

答案：只能说补到了这个特定三条件配置。现在 5 行仍少于 8 行全组合，还没有说明每个配置的数值边界、非法输入和算术输出都正确。“完整”必须说明相对于哪个有限义务集合。

**题目三：如果测试与实现都用 `x − round(x/10)` 算金额，会有什么问题？**

答案：规格要求 floor，测试复制 round 会共享错误。选择 x＝10,006 时，正确折扣为 1,000，应付 9,006；若采用通常的四舍五入，则折扣 1,001，应付 9,005。应先固定语言和舍入规则，再作明确比较。

**题目四：研究者如何检验“更强断言比更高覆盖更有用”？**

答案：不能只拿两个不同项目作比较。需要同一基线、明确的等预算干预、独立缺陷集合，以及覆盖、检错、成本的共同记录。若用已有测试能杀死的变异筛选评价对象，还需说明这个选择对结论的偏向。这个实验设计是后续研究建议，本教材没有执行。

**本章的总判断**：选样说明为什么运行这些输入；结构说明程序哪些机制被触及；判定说明哪些行为被认作正确；研究设计说明这些观察能支持多强的推广。把四者连起来，测试才从“跑过了”变成有边界、可讨论的证据。
